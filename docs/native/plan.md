# OpenCut → Native Rust + GPUI — Master Plan

> Reimplement the OpenCut web video editor as a **native Rust desktop app with a GPUI front-end**, following the **core-first** architecture decided in the desktop-architecture research.
> Generated from a 9-agent audit + roadmap workflow. Goal: **native performance, high throughput, low memory**, with a native MCP server.

## Strategy in one paragraph
This roadmap ports the OpenCut web video editor (TypeScript/React over an already-native wgpu compositor in rust/crates/{compositor,effects,masks,gpu,time,bridge}) to a native Rust app with a GPUI front-end, following the pre-decided core-first architecture. Strategy: de-risk the three hardest unknowns first (GPU/GPUI zero-readback interop, media codec licensing/hwaccel, text-raster metric parity), then build ONE framework-agnostic headless engine crate `opencut-core` whose serde-tagged Command/Query enum is simultaneously the undo/redo surface, the autosave/persistence trigger, the preview/scene-build input, AND the MCP tool surface — one dispatch path gives all four for free. Then expose it over MCP (rmcp), then wrap it in a GPUI UI shell (with a Tauri disjoint-surface fallback on the SAME core if the GPUI health gate fails), then harden for 4K60 + hw-decode stability and ship signed cross-platform. KEY REUSE: the wgpu compositor and its FrameDescriptor wire format (already native Rust structs in frame.rs) are reused verbatim; the port replaces only (a) the TS scene-graph/resolve, (b) Canvas2D rasterization, (c) the serde-wasm boundary (dropped — build structs in-process, upload wgpu textures), and (d) mediabunny/WebCodecs export -> ffmpeg. ARCHITECTURE INVARIANTS enforced throughout: the process-global EditorCore singleton becomes an owned Editor struct; the 12 cross-referencing managers collapse into one central EditorState with stateless free-function modules (avoids Rust &mut aliasing / Arc<RwLock>-per-manager deadlocks); imbl persistent Vectors back SceneTracks so per-command snapshots and the 60fps drag preview-overlay are O(1)-clone; the 9-manager useSyncExternalStore bridge collapses into a coalesced EventBus (DomainFlags + version counters, one event per committed command); rust/crates/time supplies bit-identical MediaTime tick math. Every subsystem from the four cluster inventories PLUS the ten completeness-critic additions (params registry, gradients, actions/keybindings + its own migration chain, stickers library, graphics definitions, sounds/Freesound, guides/grid overlays, subtitle SRT/ASS formats, fps utils, motion presets) is assigned to a phase. EXPLICITLY OUT OF SCOPE for the native editor (recorded decision, not a gap): the server (dep/apps/web/src/db, auth/), feedback/, and marketing site (blog/, changelog/, site/, app/ marketing routes). Honest wall-clock with a focused 4-8 engineer team across parallel workstreams: ~24-30 months total.

## Cross-cutting test strategy
Six pillars, enforced from Phase 0 forward. (1) UNIT — mechanical ports of the existing TS __tests__ (placement/resolve, retime split/resolve, snapping, audio-state, migrations, scene-builder-background) carried over 1:1. (2) PROPERTY (proptest) — the invariants that make the port MORE correct than the web: trimStart+duration*rate+trimEnd==sourceDuration exact in i64, undo/redo (k undos+redos == original state), selection-snapshot roundtrip identity, ripple interval-algebra (disjoint/sorted/within-source, never negative starts), imbl structural-sharing (untouched subtrees pointer-shared), fps never lowered, ParamValues forward-compat passthrough, migration additivity+idempotence. (3) GOLDEN — a strict THREE-TIER ladder because GPU output varies by driver: TIER 0 (descriptor) serialize the FrameDescriptor the native scene-builder+resolve produces for a fixture and diff JSON vs a committed snapshot (zero GPU, catches scene/resolve regressions); TIER 1 (CPU raster) tiny-skia PNG at 0 tolerance for color/gradient/mask/graphic (text and stroke get their own native goldens with a small tolerance, regenerated against the native shaper — NEVER shared with the web renderer); TIER 2 (GPU frame) whole composited frames through a software adapter (lavapipe/llvmpipe via WGPU_ADAPTER_NAME) diffed with a small per-pixel tolerance + max-diff-count budget. (4) MIGRATION FIXTURES — provenance-correct JSON captured from the RUNNING web app (P0-ARCH-02) for BOTH chains (project v0..v31 AND keybindings v2..v7), tested per-step (vN->vN+1) and full-chain (v0->v31 equality), with v21->v22 sRGB->linear pinned within 1e-6; insta snapshots make regeneration one command. (5) PERF BUDGETS — criterion benches with CI thresholds on every hot path: 1000-command execute+undo p99 + resident memory vs a Vec-clone baseline, 60fps drag on 12-track/500-element, 10k-element snapping build+resolve under a mousemove budget, audio-callback deadline with an rtrb starvation counter (zero underruns), export throughput, migration cold-open (<50ms), and the 4K60 preview budget. (6) PARITY FIXTURES — web-captured references for serde roundtrip (byte/JSON-value equality proving wire compatibility), media-probe tables, and audio-mix reference buffers. CI runs a cross-platform matrix (macOS/Windows/Linux) with the software GPU adapter for frame goldens, C/C++ toolchain caching (FFmpeg/whisper.cpp/Signalsmith), cargo-deny licensing enforcement, and the golden-capture tooling as the single source of fixture provenance. Test-order discipline: land the pure days-scale slices (Selection, Clipboard, bookmarks, params, fps, audio-gain, subtitle formats) first to validate the owned-Editor+Command+EventBus+imbl architecture before the 1-2 month bulk.

## Key risks & mitigations
| # | Risk | Mitigation |
|---|------|-----------|
| 1 | wgpu version three-way skew: compositor/effects/masks/gpu are on wgpu 29, vello wants 28, and GPUI pins its own in-tree wgpu — two majors cannot share a Device/Texture, which breaks the entire 'share the compositor's device with the GPUI preview' plan. | P0-GPU-01 freezes ONE workspace-wide wgpu version (driven by the committed GPUI source) before any UI work and aligns all native crates to it; drop vello from v1 entirely (it also drags a second wgpu major for marginal, non-deterministic benefit). |
| 2 | GPUI is immature (crates.io 0.2.2, ~8 months stale, sparse docs, developed in-tree at Zed) and embedding a wgpu-composited texture into a GPUI element sharing the Device is unproven — the single biggest UI-integration uncertainty. | P0-GPU-04 is a hard GO/NO-GO gate BEFORE Phase 3 effort is scheduled; keep opencut-core fully headless (MCP + goldens never depend on GPUI); ship the Tauri disjoint-surface fallback (P0-GPU-05/P3-SHELL-05) on the SAME core if the gate fails; pin an exact GPUI revision. |
| 3 | FFmpeg codec licensing: linking libx264/libx265 or bundling a GPL ffmpeg makes the whole app GPL — a redistribution blocker for a proprietary desktop editor. | P0-MED-01 decides early: default LGPL FFmpeg build with GPL encoders OFF, encode via hardware encoders (VideoToolbox/NVENC/QSV/VAAPI) + LGPL software encoders (openh264/libvpx-VP9/aom-AV1/Opus/AAC); treat webm/VP9/Opus as the always-clean path; P4-HW-03 finalizes and cargo-deny enforces the matrix in CI. |
| 4 | Text metric parity: cosmic-text/parley/swash will not match browser Canvas2D measureText/fillText pixel-for-pixel (advances, actualBoundingBox, letterSpacing, 'middle' baseline), and the blast radius is huge (raster text AND selection handles AND mask text AND text-edit overlay) — existing user projects will visibly shift text. | P0-TXT-01 spikes and commits ONE shaper with a measured tolerance budget; regenerate ALL text goldens natively (never share web goldens); budget a per-font metric-calibration pass; bundle shipped fonts rather than fetching Google Fonts at runtime (P4-PKG-04). |
| 5 | Accumulated C/C++ build burden: FFmpeg + whisper.cpp (whisper-rs) + Signalsmith (ssstretch cxx) each add a native build/link dependency, and Windows (MSVC + FFmpeg dev libs + CUDA) is the classic packaging long pole. | P0-MED-03 stands up the cross-platform CI build matrix as an EARLY de-risk milestone; keep candle as a pure-Rust ASR fallback and ffmpeg-sidecar as an escape hatch; prefer in-process ffmpeg-next but explicitly budget the manual hwaccel plumbing effort. |
| 6 | Borrow-checker aliasing: the 12 TS managers hold mutable references to each other and mutate inside each other's notify() cycle, which Rust forbids; a naive Arc<RwLock>-per-manager port invites deadlocks given the dense cross-references. | Centralize ALL mutable state in one EditorState with the 12 managers as stateless free-function modules over &mut EditorState + Ctx; P0-ARCH-01 proves the model on Selection+Clipboard before the bulk; emit EventBus events post-reactor/post-ripple to avoid feedback loops. |
| 7 | Real-time audio glitches: moving from the forgiving WebAudio scheduler to a hard-real-time cpal callback means any allocation/locking in the callback causes underruns, and the device sample rate is often not 44100. | Two-thread design with ALL decode/resample/stretch off the audio thread, rtrb lock-free handoff, gain envelopes sampled at DEVICE rate in the callback; P4-PERF-03 hardens with an underrun/starvation counter and a no-allocation verification. |
| 8 | Color/bit-depth drift: the raster+compositor path is implicitly 8-bit sRGB (Bgra8), but native HEVC/AV1/ProRes decode yields 10-bit P010 / BT.709/BT.2020 surfaces — decoded video colors will drift from the browser without an explicit conversion stage. | P0-MED-02 defines an explicit YUV->RGB + transfer-function + bit-depth stage in the decode/compositor contract; P4-HW-02 validates against 10-bit HEVC/HDR fixture goldens. |
| 9 | Migration color drift: the v21->v22 project migration does sRGB->linear via an inlined transfer function (0.04045/12.92, 1.055/2.4); using palette's default conversion would make every pre-v22 project render with subtly wrong colors, and hand-authored fixtures miss real-user fields. | Reproduce the inlined transfer function verbatim in P1-PER-04 and golden-test within 1e-6 against web-captured output; capture ALL migration fixtures (both the project v0..31 AND keybindings v2..7 chains) from the running web app via P0-ARCH-02, not by hand. |
| 10 | Single-writer contention: the GPUI shell and the MCP server both mutate the same project over one SQLite store, risking SQLITE_BUSY and lost updates / autosave clobbering. | P2-MCP-01 introduces a single-writer core actor / command-queue (CoreHandle) from day one that both the shell and MCP go through, with WAL mode — designed in, not retrofitted. |
| 11 | Silent scope loss: the inventories repeatedly name cross-cluster dependencies (params registry, fps utils, gradients, graphics GraphicDefinition.render, sticker bytes, subtitle formats, motion presets) as inputs OTHER subsystems need but never assign an owner, so a build sequenced from them hits missing-dependency blockers. | Every completeness-critic addition is promoted to a real task with explicit dependency edges (P1-FND-02 params, P1-FND-03 fps, P1-GRAD-01 gradients, P1-GFX-01 graphics, P1-STK-01 stickers, P1-TXT-03 subtitle formats, P1-ANIM-04 motion presets, P1-PER-06 keybindings, P3-AST-03 sounds, P3-PRV-06 guides), and Phase 1's exit gate explicitly checks that no named dependency is unprovided. |
| 12 | GPU golden non-determinism across drivers makes whole-frame golden tests flaky and untrustworthy as regression gates. | A strict three-tier golden ladder: Tier-0 descriptor JSON (zero GPU), Tier-1 tiny-skia CPU raster at 0 tolerance, and Tier-2 whole-frame GPU goldens ONLY through a software adapter (lavapipe/llvmpipe) in CI with a small per-pixel tolerance + max-diff-count budget; text/effects/masks GPU goldens run headless. |

## Milestones
1. M0 — De-risk gates cleared (end Phase 0): workspace wgpu frozen; GPUI zero-readback preview interop GO/NO-GO decided (with Tauri fallback demo); FFmpeg backend + codec/licensing matrix chosen; text shaper committed with a measured parity budget; C/C++ CI matrix green on macOS/Windows/Linux; owned-Editor borrow model proven on Selection+Clipboard; golden-fixture capture tooling producing committed fixtures.
2. M1 — First pixels (early Phase 1): the native GpuContext + reused compositor render a hand-built FrameDescriptor to a winit/wgpu window and to a PNG, with correct format/alignment/swizzle (P0-GPU-03 + P1-RND-03/04).
3. M2 — Headless edit & persist (mid Phase 1): a CLI loads a fixture project through the full 31-step migration chain, edits it via the Command API with correct undo/redo, and autosaves to SQLite + native blob store (P1-PER-* + P1-CORE-* + P1-TL-13).
4. M3 — Headless render & export (Phase 1 exit): the SAME fixture resolves + rasterizes (tiny-skia) + composites through the native compositor and exports to MP4 AND WebM with mixed audio, validated by all three golden tiers plus migration/property/perf-smoke suites — the first true end-to-end product capability, with no UI.
5. M4 — MCP surface live (Phase 2 exit): an MCP client (rmcp) lists/opens/creates/deletes projects, mutates the timeline through undoable commands, and reads project/timeline/media resources, all serialized through the single-writer core actor over one SQLite store.
6. M5 — Interactive GPUI editor (Phase 3 exit / GPUI health gate): the native shell shows live preview via the embedded wgpu surface, timeline drag/resize/seek/zoom drives the core with correct undo, inspector + graph editor + effects/masks panels work, the asset browser + stickers/sounds/subtitles libraries + actions/keybindings are functional, real-time cpal playback is A/V-synced, and a11y + IME are in place — OR the Tauri fallback delivers the same editing loop on the same core.
7. M6 — Ship (Phase 4 exit): 4K/60 preview within frame budget; hardware decode stable with SW fallback and correct 10-bit/HDR color; a license-clean encode matrix; signed/notarized installers with auto-update, bundled fonts, and model-download UX on macOS/Windows/Linux; full golden/perf/migration/e2e suites green cross-platform; degraded no-GPU mode ships.

## Scope
**Out of scope for the native editor** (recorded decision, not a gap): the server (`dep/apps/web/src/db`, `auth/`), `feedback/`, and the marketing site (`blog/`, `changelog/`, `site/`, marketing routes). The native app is the editor + engine + MCP only.

### Completeness-critic additions (folded into the phases)
- PARAMS REGISTRY (dep/apps/web/src/params/, 794 LOC: registry.ts + index.ts) — NO subsystem owns it, yet it is a hard dependency of nearly everything. buildDefaultParamValues seeds every element/effect/mask/graphic default; parseColorToLinearRgba/formatLinearRgba are called by animation-channel-curve-math's color-fold (that subsystem lists 'params color parse/format' as a dep with no provider), by masks, gradients, and text color resolution. The untyped ParamValues bag + typed ParamDefinition contract is referenced as a cross-cluster dep in effects-registry, masks-shapes, animation-param-channels, and the domain-model subsystem — but there is no task, no testCases, no effort. This must be an explicit FOUNDATIONAL subsystem (days-to-1-2-weeks) that lands before animation/effects/masks.
- GRADIENTS (dep/apps/web/src/gradients/parser.ts 652 LOC + canvas.ts 923 LOC = ~1577 LOC) — grossly underspecified. The rendering cluster reduces it to 'drawCssBackground -> lightningcss/csscolorparser' as a one-line cross-dep. In reality this is a full CSS gradient PARSER (linear/radial/conic, ang/side/corner directions, color stops with positions, interpolation) AND a canvas RASTERIZER (drawing gradients into a surface). lightningcss parses CSS but does NOT rasterize gradients into a pixmap; tiny-skia gradient shaders must be driven from the parsed model. Needs its own subsystem with golden tests (color used by background AND text background AND graphic fills).
- ACTIONS & KEYBINDINGS SYSTEM (dep/apps/web/src/actions/, ~10 files) — entirely absent from all four clusters. ~50 action definitions (definitions.ts), an action registry, keybinding matching (keybinding.ts), use-action-handler / use-editor-actions / use-keyboard-shortcuts-help, a customizable keybindings store, AND its OWN persistence layer with a SEPARATE 6-step migration chain (actions/keybindings/migrations/ v2-to-v3 ... v6-to-v7). The MCP Command enum covers editing verbs, but the keyboard-shortcut -> action -> command dispatch layer, customizable bindings, and the shortcuts-help UI are a distinct user-facing subsystem. Critically, the persistence cluster enumerated projects/media/saved-sounds/motion-presets stores but MISSED the keybindings persisted-state + its migration chain — a second golden-fixture surface.
- STICKERS content subsystem (dep/apps/web/src/stickers/, ~11 files: registry, resolver, providers/{flags,logos,shapes,countries-data}, categories, intrinsic-size, sticker-id, stickers-store) — the Sticker ELEMENT type is modeled and StickerNode rasterization is noted, but the sticker LIBRARY (Iconify-based resolution, flag/logo/shape providers, category browsing, search, intrinsic-size capture at insert) has no task. resolve.ts only warns 'native must vendor sticker SVGs locally'. Needs its own subsystem (asset provider + resolver + local vendoring).
- GRAPHICS definitions registry (dep/apps/web/src/graphics/, definitions/{rectangle,ellipse,polygon,star}, registry.ts, stroke.ts, types.ts, resolveGraphicElementParamsAtTime) — only appears as the raster cross-dep 'Graphics cluster owns GraphicDefinition.render'. The DefinitionRegistry, default-instance builders, stroke handling, and per-frame animated-param resolution (resolveGraphicElementParamsAtTime, called every frame in resolve.ts) are not tasked anywhere. Parallel to effects-registry/masks-registry but with no owning subsystem.
- SOUNDS / FREESOUND library (dep/apps/web/src/sounds/ + server proxy app/api/sounds/search/route.ts) — only the saved_sounds STORAGE table is covered by the persistence cluster. The Freesound API search CLIENT (use-sound-search, SoundEffect model, preview/download URLs, licensing), saved-sound management UI logic, and library-audio element insertion/resolution are untasked. Library audio elements (BaseAudioElement sourceType='library') depend on this to resolve their source. Needs a network client + saved-sounds-management task (note: native must replace the server proxy with a direct Freesound client).
- GUIDES / grid & safe-area overlays (dep/apps/web/src/guides/: grid.ts, definitions/{grid,platforms,tiktok-layout,custom}, registry, preview-overlay) — completely absent. Preview overlay feature for composition grids, platform safe-area layouts (TikTok/etc), and custom guides. Small but user-facing; belongs as a preview-shell overlay task.
- SUBTITLES file import/export (dep/apps/web/src/subtitles/: srt.ts 98, ass.ts 514, parse.ts, build-subtitle-text-element.ts 348, insert.ts) — conflated into 'transcription-subtitles' which only actually specifies Whisper + caption chunking. The SRT and ASS parsers/builders (ASS alone is 514 LOC) and build-subtitle-text-element are distinct from ASR and not called out with testCases. Underspecified: subtitle FILE import/export is its own pure-logic port.
- FPS handling (dep/apps/web/src/fps/: utils.ts 104, presets.ts, defaults.ts) — referenced repeatedly as a 'fps utils' cross-dep (placement, export framecount, ratchet in ProjectManager) but never homed. frameRateToFloat, standard-rate snapping/tolerance, detect-fps-from-asset, getRaisedProjectFpsForImportedMedia, fps presets. Small pure port but should be an explicit shared module the time crate or a core util owns.
- MOTION PRESETS (dep/apps/web/src/motion-presets/: preset-ops.ts 113, motion-presets-store.ts, types.ts, __tests__ + commands/timeline/element/effects/apply-motion-preset.ts) — acknowledged in fragments (Command::ApplyMotionPreset; animation-param-channels says 'motion-preset id-remap helper should live here'; persistence has the motion_presets table) but no subsystem owns preset-ops (capture effects+animations from an element, stamp onto others with effect-id remapping, CRUD store). Scattered across three clusters with no single task or test plan.

### Feasibility-critic adjustments (crate/approach corrections applied)
- Decide and freeze ONE workspace-wide wgpu version FIRST, chosen to satisfy whichever GPUI source you commit to, and align the compositor/effects/masks/gpu crates to it. Drop vello from v1 (revisit only if a GPU-native text/vector preview path becomes necessary and a single-wgpu-version vello is available). This removes the wgpu-28/29/gpui three-way skew.
- Run a GPUI spike BEFORE scheduling the preview/timeline UI: prove (a) you can composite a wgpu texture produced by your Compositor into a GPUI custom element sharing the same Device, and (b) the gpui-component widget set covers the timeline/inspector needs. Pin an exact GPUI revision (crates.io 0.2.2 or a vendored Zed commit) and budget for API churn. Keep the core (opencut-core) fully headless so the MCP path and golden tests never depend on GPUI landing.
- Resolve FFmpeg licensing explicitly and early: default to an LGPL FFmpeg build with GPL encoders OFF, and get encode coverage from hardware encoders (VideoToolbox/NVENC/QSV/VAAPI) plus LGPL software encoders (openh264 for H.264, libvpx VP9, libaom/SVT-AV1, Opus/AAC). Treat webm/VP9/Opus as the always-available clean-room export path. Document the codec/licensing matrix as a first-class artifact.
- Prefer ffmpeg-next (single-dependency, in-process, exact PTS control) over ffmpeg-sidecar for the editor decode/export path so you are not shipping/downloading a ~100MB binary and inheriting its build's license, but budget real effort for the manual hwaccel plumbing (device ctx, hw-frame mapping, NV12/P010->RGB conversion, SW fallback). Re-evaluate gstreamer-rs only if the hwaccel plumbing proves worse than its heavier runtime footprint — do not assume ffmpeg 'just works' for hardware decode.
- Add an explicit color-conversion + bit-depth stage to the decode/compositor contract (YUV->RGB, transfer function, 8-bit vs 10-bit) rather than assuming 8-bit sRGB; capture per-fixture color goldens that include a 10-bit HEVC source.
- For text, regenerate ALL text goldens against the native shaper (never share web goldens), pick ONE shaper and commit (cosmic-text is the pragmatic default given color-emoji+bidi+HarfRust; parley only if you need its Google-font-stack layout — and pin its version because of its aggressive MSRV/patch-bump policy), and plan a per-font metric-calibration pass. Bundle the fonts you ship rather than fetching Google Fonts at runtime.
- For transcription, default to whisper-rs for the accel matrix but keep candle as the pure-Rust fallback to cut the C++ build burden on platforms where whisper.cpp is painful; run inference off-thread with the existing cancel/session-id lifecycle, and gate models by disk/download UX (large-v3-turbo ~1.5GB).
- Consolidate the native-build story: FFmpeg + whisper.cpp + Signalsmith(cxx) are three C/C++ deps — set up the cross-platform (especially Windows/MSVC + CUDA) CI build matrix early as a de-risking milestone, and prefer ssstretch (actively maintained cxx bindings) for pitch-preserving stretch, validating output perceptually (energy/duration/pitch-FFT) rather than byte-for-byte against soundtouchjs.
- Keep the MCP server (rmcp) a strictly thin transport over opencut-core with a SINGLE-WRITER core actor/command-queue, since rusqlite (WAL) plus a shared editor state means the GPUI shell and MCP server must serialize writes to avoid SQLITE_BUSY and lost updates — design this from day one, not retrofitted.
- Reproduce the exact inlined sRGB->linear transfer function for the v21->v22 project migration rather than trusting palette's default conversion, and capture per-version migration goldens from the running web app (not hand-authored fixtures) so pre-v22 projects render with identical colors.
